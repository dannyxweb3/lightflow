# 服务端实现与验收记录

## 本次交付

交付仅监听 HTTP 的 Go 控制面、PostgreSQL 迁移、受监管的 Hysteria2 协议网关、无内置 HTTPS 代理的 Compose 文件、初始化脚本、API 契约及测试。完整项目需求还包括桌面客户端、TUN、智能分流、DNS、Kill Switch、三平台网络恢复、其他协议和制品更新执行。这些部分仍未实现，因此不能按原需求第 33 节标记 V1 完成。

此次服务端闭环为：管理员建账户和订阅 → 登录 → 注册设备公钥 → 查询国家 → 设备签名请求连接 → PG 锁定配额并创建租约 → 私网 HTTP 加独立令牌的网关拉取授权 → 网关 ACK → 返回临时凭据 → Hysteria2 建立加密连接 → 续租或撤销 → 网关关闭已建立流。

## 实现决定

| 设计项 | 当前实现 | 后续要求 |
| --- | --- | --- |
| 身份 | 管理员建邮箱账户，PBKDF2 密码，短期访问令牌与旋转刷新令牌 | 若接 OIDC，迁移身份主体并补完整设备/会话迁移；管理权限改 RBAC、MFA |
| 权益 | 每账户一份当前订阅，设备和并发数量在 PG 事务中检查 | 套餐历史、运营系统及支付事件 |
| 节点选择 | 过滤国家/在线/容量，选择占用率较低的 Hysteria2 入口 | 多候选、延迟/成功率/稳定性评分及 TCP 协议回退 |
| 网关同步 | 每 2 秒拉完整授权快照并 ACK；Agent 以单调时钟到期 | 多网关规模扩大后分片、增量事件和定期对账 |
| 强制撤销 | Hysteria2 HTTP auth、`/online` 与 `/kick`，500ms 周期检查 | 全协议对应强制踢除和网关凭据动态化 |
| 故障策略 | 统计接口连续故障即终止网关；控制面离线不再续租 | 更细粒度高可用、异地多实例和观测告警 |
| 策略/更新 | Ed25519 签名 JSON 封装发布 | 规则构建、下载、客户端兼容检查、灰度及回滚执行 |

当前没有 Redis。事务配额、限流、会话与身份均由 PostgreSQL 保持正确性；首版部署规模无需第二个状态系统。用户账号密码方式是本次服务端启动阶段可运行的入口；总体设计原先推荐 OIDC，但具体身份服务未指定。正式开放商业用户前需要决定 OIDC/账户体系与运营权益来源。

网关安全边界按官方 [Hysteria2 HTTP 认证格式](https://v2.hysteria.network/docs/advanced/Full-Server-Config/) 和 [Traffic Stats API 的 `/kick` 行为](https://v2.hysteria.network/docs/advanced/Traffic-Stats-API/) 实现。`/kick` 本身允许客户端尝试重连，因此 Agent 同时移除授权、拒绝下一次认证，并踢除当前连接。每租约只允许一个 Hysteria2 在线实例；超过一个会被踢除。

## 已完成验证

- `go test -race -count=1 ./...`：已在本机 PostgreSQL 16.9 上运行通过，包含数据库事务及真实网关测试。
- 真实进程为 Hysteria2 v2.12.3；验证了加密 TCP 隧道、设备删除后现存流断开、控制面关闭后现存流到租约截止断开，以及网关令牌轮换后旧 Agent 停止和出口流断开。
- API 集成测试覆盖设备上限、并发竞争、幂等重试和请求冲突、设备签名重放、跨账户会话访问、刷新令牌重放撤销、订阅失效、网关令牌身份隔离及轮换和签名文档验签。
- 使用本机 PostgreSQL 独立 schema 实际启动纯 HTTP `nimbus control`，`/readyz` 返回 200；内部端口未认证请求返回 401，公开端口对内部路由返回 404。
- `go vet ./...`、`go build ./cmd/nimbus`、OpenAPI JSON 解析通过。
- `docker compose config --quiet` 和独立网关 Compose 配置检查通过；本开发主机没有 Docker socket 权限，因此**镜像构建和容器启动尚未在本机实测**。CI 工作流已加入 Compose 构建/启动与镜像内协议二进制测试，这些步骤仍需 CI 实际运行确认。

## 上线前缺口与限制

1. 首版仅 Hysteria2/QUIC。UDP 被封锁时无法自动回退 TCP；Snell、VLESS/Reality、VMess、Trojan 的网关授权与踢除仍需分别验证。QUIC 是传输，Reality 是 VLESS 的参数组合。
2. 一次连接计划只返回一个候选网关，按占用率选取；没有延迟、稳定性、成功率权重，也没有无缝网关切换。
3. 智能分流、DNS 路径、Kill Switch 和系统网络恢复由桌面端/本地网络服务负责，这部分代码尚未建立。服务端 `mode` 字段仅校验为 smart/global，不在网关实现本地分流。
4. 默认生成的网关证书来自私有 CA；公网客户端需要可信证书链或预置信任。管理后台已有单管理员密码和数据库会话，但尚无 RBAC/MFA；管理入口应限制在本机或受控网络。生产公网管理需增加带 MFA 的身份访问层及更完整的审计告警。
5. `login_limits` 按直接对端 IP 计数。反向代理后所有登录请求共享一个代理地址的 IP 桶，用户规模扩大前需要可信代理提取与边缘限流。
6. 规则和制品仅有签名元数据发布 API，没有对象存储、规则构建、灰度兼容矩阵或客户端更新执行。上传 JSON 未经业务 schema 详细校验；客户端必须把签名验证和 schema 验证分开执行。
7. 网关 ACL 拒绝常见内网/保留地址，实际公网部署仍需按目标云厂商网络实现出口防火墙，防止 DNS 重绑定或云元数据地址访问。该出口策略尚未做跨环境抓包验收。
8. 密钥轮换是停机维护流程，未提供平滑多密钥轮换；操作步骤见 `DEPLOYMENT.md`。当前 Compose 只部署单控制面/数据库实例，不提供数据库高可用。

下一阶段应先在有 Docker 权限的 CI/部署机跑通镜像和 Compose，并把真实协议镜像版本纳入回归测试；然后推进桌面本地服务和 TCP 协议网关，直至原需求的三平台闭环逐项验收。
