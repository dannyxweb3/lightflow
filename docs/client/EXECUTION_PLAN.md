## C0 下一步操作顺序

1. 保存已有提交与启动器修复，合并 `origin/main@7bd2b26`，目录归属写入 `AGENTS.md`。此次远程仍包含旧基线，使用正常 merge，不 reset 丢弃客户端工作。
2. 按最新 S0 交付使用独立账号 `.local/windows-s0-account.json`；本轮只检查文件名，确认本地尚缺此文件。通过受控方式取得，保留生产账号隔离，不输出密码。这是开发者同步资料，不是用户使用客户端的流程。
3. 实测 Windows 到测试 API 的 HTTPS、CA/IP 校验及 Date；登录、临时设备证明、申请全新租约；核对候选地址、端口、SNI、协议和期限。问题附错误码、请求 ID，交给服务端。
4. 核验 Mihomo/驱动/规则版本与 SHA256；检查核心控制管道 ACL。受限 ProgramData 目录手写单节点配置，先验证转发，再启用 TUN；实验前记录网络基线及回收步骤。
5. 智能/全局分别访问固定国内/海外目标，在物理网卡与 TUN 留抓包摘要；覆盖 UDP/TCP 53、LAN DNS、自带 DoH、硬编码 IPv6、无 IPv6 网关与网段冲突。
6. 正常断开、强杀核心、网络切换、睡眠唤醒，记录恢复秒数及残留。其他 VPN/Hyper-V 冲突时拒绝并报告，只清理产品自有对象。
7. 提交经过实测的 `MIHOMO_BASELINE.md` 和 `M0_EVIDENCE.md`，含脱敏配置、hash、测试次数、前后网络差异、抓包结论与限制。证据通过后进入 C1，并给服务端提供回退联调基础。

两份 M0′ 证据文档尚未完成，不提前填写 PASS。M0′ 不继续扩展演示界面，也不以浏览器能开网页代替路径/恢复验证。

## 关键验收

| 项目 | 验收证据 |
| --- | --- |
| 智能分流 | 国内测试目标物理直连，海外仅经网关加密流量；无隐藏直连回退 |
| 全局 | 非必要例外的互联网流量均走隧道，私网行为匹配设置 |
| DNS/IPv6 | 真实 DHCP/LAN DNS、明文 53、加密 DNS、硬编码 IPv6 的路径；不支持部分明确拒绝 |
| 取消/恢复 | 断开不会被旧授权/探测回调重新连上；恢复≤5 秒为目标，未达标有实测与阻塞记录 |
| 租约 | pending 同键同 body 新 nonce；续租跨 token 刷新；过期/撤销停转发；普通断开不删设备 |
| 回退 | 先释放后新租约，同国家；≤20 秒计时包含授权等待，释放失败不另建会话 |
| 安全/交付 | 未授权用户不能控服务或核心；UI/日志无秘密；正式客户端双击操作，无 Vite 1420、SCP 或手配节点 |

代码变更按共享规则执行 frontend build/test、Go test/vet、Rust check；Windows 实现用 build tag，依赖变化还在 Linux 验证。真实网络实验另留证据，mock 与编译不能替代。
